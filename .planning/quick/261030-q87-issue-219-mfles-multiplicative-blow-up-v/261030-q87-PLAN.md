# Plan: #219 MFLES multiplicative blow-up on a near-zero month

## What
Issue #219: MFLES auto-selects multiplicative (log) mode for a positive series with one
near-zero month; the unfloored `ln()` crater is overfit by the Fourier seasonal and `exp()`
back-transform runs away to ~13x the level.

## Finding before coding
`origin/main` already contains a fix (commits 2d6eb9b, d36de76, 66bd423, released in v0.15.10):
three guards in `src/models/mfles.rs` — auto-additive fallback when `min/median < 0.10`,
log-floor at `0.01 * median`, back-transform clamp at `10 * insample_max`. The issue reporter
validated it on the production panel (comment on the issue). The existing regression test
`tests/issue_219_mfles_multiplicative_runaway.rs` uses a *synthetic* stand-in (min = 1.0 in a
flat ~2000 series), not the issue's actual repro series.

## How
Do not re-implement the fix. Close the remaining gap:
1. Add a regression test using the **exact** repro series from the issue (min = 12, next
   lowest 876, level ~2000, one 5998 peak) for (a) auto mode and (b) forced multiplicative mode
   with `max_rounds = 50` (issue's fitted params).
2. Prove it fails before / passes after: run the new test against v0.15.8 (pre-fix) in a
   throwaway worktree and against the current branch; record forecast numbers.
