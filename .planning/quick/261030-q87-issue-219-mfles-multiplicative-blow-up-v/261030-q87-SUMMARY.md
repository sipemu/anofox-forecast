# Summary: #219 MFLES multiplicative blow-up (verification only, no code change)

## Outcome
The fix for #219 was **already on `origin/main`** before this task started (commits `2d6eb9b`
RED test, `d36de76` fix, `66bd423` serde-default follow-up; released in v0.15.10). The issue is
still open on GitHub, but its last comment (from the reporter) validates the fix on the
production panel (step-0 MFLES forecast 26,286 -> 1,778 on the affected series; zero runaways in
a 7,415-series run) and says it can be closed. No new fix was written; re-implementing it would
have duplicated shipped code.

Guards present in `src/models/mfles.rs` (verified in source):
1. Auto mode falls back to additive when `min / median < 0.10` (`MULT_AUTO_TAU`).
2. Log transform winsorises `v.max(0.01 * median)` before `ln()` (`MULT_LOG_FLOOR_FRAC`).
3. Multiplicative back-transform clamped to `[0, 10 * insample_max]` (`MULT_BACK_CLAMP_K`).

## Measured before/after (re-run today, not copied from old commits)
Existing regression test `tests/issue_219_mfles_multiplicative_runaway.rs` (synthetic 24-month
series, level ~2,000, one month = 1.0), run against tag `v0.15.8` (pre-fix) in a throwaway
worktree and against `origin/main` (v0.18.0):

| 12-step forecast, `MFLES::new(vec![12])` | v0.15.8 (pre-fix) | v0.18.0 (post-fix) |
|---|--:|--:|
| auto mode: step 0 | 14,049 | 3,172 |
| auto mode: max | 15,378 (7.7x level) | 3,172 (1.6x level) |
| auto mode: mean | 12,725 | 2,818 |
| forced multiplicative: max | 15,378 | 11,210 (< 10x cap 24,000) |

Test outcomes: v0.15.8 -> 2 of 3 tests FAIL (`no_multiplicative_runaway`: forecast_max=15378 >=
5000; `auto_mode_selects_additive`: mean 12725); v0.18.0 -> 3/3 pass.

## Deviation: exact issue series does not reproduce the runaway
I wrote a test with the **exact 17 monthly values** listed in the issue (min 12, next-lowest 876)
expecting it to fail on v0.15.8. It does not: on v0.15.8 that 17-point excerpt selects
multiplicative mode but forecasts stay in range (step 0 = 23, max = 3,699). The issue's table
is an excerpt of a longer production history (fewer than 2 seasons are shown), and the runaway
needs the longer history, which is not public. Because the test passed both before and after
the fix it is not a regression test, so I discarded it rather than commit a test that proves
nothing. The synthetic test above remains the failing-before/passing-after guard.

## Observation for the maintainer (not changed)
On that same 17-point excerpt, post-fix auto mode (now additive) gives **negative** forecasts
for a strictly positive demand series: step 0 = -1,431, step 6 = -378, step 7 = -519. Pre-fix
(multiplicative) step 0 was 23. The additive fallback removes the runaway but does not enforce
non-negativity. Whether MFLES should clip to >= 0 when the training data is non-negative is a
behaviour change outside #219's scope and is left as a decision for the maintainer.
