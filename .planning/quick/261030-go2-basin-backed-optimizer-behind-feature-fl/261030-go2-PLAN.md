<objective>
GH issue #234, step 1: put basin 3.1.0 (pinned) behind the existing `utils::optimization` signatures as an evaluation backend. Then measure parity and timing against the hand-rolled optimizers for SES/Holt/ETS/ARIMA/Theta/Croston/GARCH/TBATS. The default build stays unchanged and the hand-rolled optimizers stay in place.

Routing decision (the orchestrator asked for a choice and a justification). The `basin` cargo feature compiles the dependency and the basin backend: `nelder_mead_basin` / `lbfgs_optimize_basin` are public, unit-tested, clippy-checked and doc-checked. Routing the public `nelder_mead` / `lbfgs_optimize` to basin needs the feature AND the compiler cfg `anofox_basin_optimizer` (passed with `RUSTFLAGS="--cfg anofox_basin_optimizer"`). Reasons:
(1) `.github/workflows/ci.yml` runs `cargo test --all-features` on stable/beta/nightly and `cargo llvm-cov --all-features`. A feature-only switch would run the whole R/statsforecast reference suite against an optimizer that has not been validated. The parity failures this task is meant to *measure* would turn CI red.
(2) Cargo features unify across a dependency graph. If any crate in a downstream graph enabled `basin`, every model fit for every consumer would silently change. A switch that changes numeric behavior should not ship as an additive feature until parity is proven (issue step 3 flips the default).
(3) `--all-features` still builds and tests the basin code, so it cannot rot.
This differs from the literal wording "when the `basin` feature is on, route them". The report must state the deviation and its reasons, and the summary returned to the user must mention it too. It is reversible: step 3 can change the cfg gate to the feature alone.

Purpose: get evidence (not opinions) on whether basin can replace the in-house optimizers. This follows the project's Core Value: every change is backed by a before/after number.
Output: basin backend + cfg routing, parity probe example, `docs/audits/basin-optimizer-parity.md`.
</objective>

```rust
use basin::{ApplicationStop, Backtracking, BoxBounds, Constrained, ConstraintSet, CostFunction,
            Executor, FirstOrderState, Gradient, Lbfgs, NelderMead, SimplexProgress,
            Termination, TerminationCode};
// Adapter: struct Obj<'a, F: Fn(&[f64]) -> f64> { f: &'a F, .. }
//   impl CostFunction: type Param = Vec<f64>; type Output = f64; type Error = std::convert::Infallible;
//   impl Gradient:     type Gradient = Vec<f64>;
// Bounded problem:     Constrained::new(obj, ConstraintSet::new().with_bounds(BoxBounds::new(Some(lo), Some(hi))))
//                      (+/-inf entries are valid "no bound" markers; NaN or lo > hi make run() return Err)
// Nelder-Mead:         NelderMead::with_params(alpha, beta, gamma, delta)   // panics if alpha<=0, beta<=1, gamma or delta not in (0,1)
//                        [.projected()]                                     // bounded variant: clamps every trial vertex
//                        .with_absolute_simplex_size_tolerance(None).with_relative_simplex_size_tolerance(None)
//                        .with_relative_simplex_cost_tolerance(None).with_absolute_simplex_cost_tolerance(tol)
//                      Executor::new(problem, solver, SimplexProgress::from_simplex(vertices /* n+1 Vec<f64> */))
//                        .max_iter(n as u64)
//                        .no_objective_improvement(window as u64, tol)       // panics if window == 0 or tol < 0 / non-finite
//                        .stop_when(move |s: &SimplexProgress<Vec<f64>, f64>| -> Option<ApplicationStop> { .. })  // FnMut + 'static
//                        .run()  -> Result<OptimizationResult<_>, _>
// L-BFGS-B:            Lbfgs::with_line_search(Backtracking::new().rho(r).with_sufficient_decrease_coefficient(c).max_iter(k as u32))
//                        .with_m_capacity(m)                               // panics if m == 0
//                        .with_absolute_projected_gradient_tolerance(tol)
//                      Executor::new(constrained_problem, solver, FirstOrderState::new(x0)).max_iter(n as u64).run()
// L-BFGS (unbounded):  Lbfgs::with_line_search(ls).unbounded().with_m_capacity(m).with_absolute_gradient_tolerance(tol)
// Result reads:        r.best_param() -> &Vec<f64>, r.best_cost() -> f64, r.iter() -> u64,
//                      r.report.termination (Termination<f64>: Converged(_) | Limit(_) | Stalled(_) | Failed(_) | Application(_) | ..),
//                      r.report.code() -> TerminationCode (SimplexTolerance, NoImprovement, GradientTolerance,
//                      ProjectedGradientTolerance, MaxIter, ..)
```

Coefficient mapping, legacy to basin: `NelderMeadConfig.alpha` (reflection) maps to alpha, `.gamma` (expansion) to beta, `.rho` (contraction) to gamma, `.sigma` (shrink) to delta. The basin acceptance rules for reflection, expansion, outside/inside contraction and shrink are the same as the legacy `try_reflection_expansion` / `try_contraction` / `shrink_simplex`.
